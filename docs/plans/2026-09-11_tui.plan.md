# curses TUI for the PIM (View-only)

Visual polish after this plan (diary paint, search retry, ADR-0018) is recorded in `docs/plans/2026-09-12_tui-improvement.plan.md`.

The submitted View becomes a full-screen **stdlib `curses`** terminal: structured panes, a visible selection, colour-coded Alarm Alerts, and keyboard navigation. Appendix B behaviour, MVC, and the existing command/wizard language stay.

This **explicitly reopens ADR-0004** (the lock that said the submitted View is clear-and-redraw, not curses). The brief still holds: Python standard library only, no GUI window, no extra product features, no pip.

## Why this is allowed (and what stays locked)

| Locked | Unchanged |
|---|---|
| US1–US11, four PIR types, criterion grammar | yes |
| MVC, `model` as deep test surface, no threads/ANSI in `model` | yes |
| Prompted create/modify; one criterion line for search (ADR-0013) | yes |
| Verb commands `create` / `search` / `modify` / … (ADR-0016) | yes, plus keys that do not replace them |
| In-process OVERDUE/SOON, dismissed in View memory, injected `now` | yes |
| Failed commands atomic; dirty load/quit; `.pim` JSON | yes |
| No Textual/Rich/prompt_toolkit/Click, no pip | yes |

| Reopened | New decision |
|---|---|
| ADR-0004 “not curses” | Interactive TTY uses `curses`; scripted/non-TTY keeps the current line UI so tests still inject stdin/stdout |
| ADR-0010 “stdin thread is the only loop” | TTY loop is `get_wch` + `timeout(500)`. Non-TTY loop stays Queue + stdin-reader |
| PRODUCT / AGENTS “curses out of scope” | Align those files with the new ADR so they do not diverge |

Out of scope remains: GUI, third-party TUI, recurrence, PIR links, OS notifications, snooze, unique labels, fuzzy search, changing type.

## Design intent

This is a **paper organiser in a terminal**, not a code editor and not a generic ncurses demo (blue menu, green-on-black).

- **Signature:** the Alarm Alert is a full-width sticky across the top — red OVERDUE / amber SOON — always visible without typing Enter. Dismiss is the first thing the eye can act on.
- **Structure:** master–detail. Current Result is an index-card list; the selected PIR is the card face. Search is a filter on the index, not a separate screen.
- **Voice:** the same English verbs as today. The footer names keys in the user’s words (`select`, `search`, `create`), not implementation names.
- **Empty and error:** empty list invites `create note`. Status line names the fix, never a traceback.

Colour is curses colour pairs (stdlib), with a monochrome fallback when `curses.has_colors()` is false. No `colorama`, no ANSI helper library.

Non-TTY (tests, redirected stdout): keep today’s linear `_layout()` so `tests/unit`, `tests/integration`, and `tests/e2e` stay scriptable.

## Interaction (intuitive, not a new language)

The bottom line remains the prompt. Wizards and the criterion line are unchanged (ADR-0013). Keys are accelerators around that prompt.

**When the prompt is empty and no wizard is open**

| Key | Action |
|---|---|
| `↑` `↓` / `j` `k` | Select previous/next row of Current Result (same as typing the row number) |
| `PgUp` `PgDn` | Page the list |
| `Home` `End` | First / last row |
| `/` | Start search (same as `search` with no argument) |
| `c` | Start create |
| `m` | Modify selection |
| `p` | Print selection |
| `P` | Print all (Current Result) |
| `x` or `Delete` | Delete selection (still confirms `y`/`n`) |
| `d` | Dismiss the first visible alarm |
| `w` | Save (or prompt path if untitled) |
| `?` | Help overlay; any key closes it |
| `q` | Quit (dirty → save / discard / cancel) |

Letter keys that start a **verb** (`create`, `search`, `clear`, …) still work if the user types the full word and Enter. Single-letter accelerators fire only on an empty prompt so they do not steal `clear` vs `c`.

**While typing a command or answering a wizard**

- Ordinary editing: Unicode, Backspace, Left/Right in the input line.
- Enter submits one line to the existing `_handle_line` / prompt stack.
- Esc cancels the current prompt (same as today’s “command cancelled”), not the process.
- List navigation is paused so field text is not turned into selection.

**Dialogs (curses boxes, same answers as today)**

- Delete: `y` / `n`
- Dirty load/quit: `save` / `discard` / `cancel` (and `s` / `d` / `c`)
- Save-as overwrite: `y` / `n`

Print: if `print_text` is set, a scrollable overlay (in-process, not a pager process). `q` / Enter / Esc closes it. `print all` still means Current Result.

Create/modify stay **field-by-field at the prompt**, not a multi-field form. That keeps US6 “empty enter keeps the field” and the demo script.

## Visual system (curses pairs, 8-colour safe)

Palette is named roles, not raw numbers. On 8-colour terminals (macOS Terminal.app default):

| Role | Pair | Use |
|---|---|---|
| `title` | cyan + bold | Bound File, dirty `*` |
| `overdue` | white on red | Alarm banner OVERDUE |
| `soon` | black on yellow | Alarm banner SOON |
| `select` | black on cyan | Current Result cursor row |
| `type` | type-coloured, bold | `note` / `task` / `event` / `contact` |
| `status_err` | red | Failed command |
| `status_ok` | green | Created / saved |
| `muted` | dim / white | Footer hints, empty states |
| `frame` | default ACS line art | Pane borders (`ACS_HLINE` etc., not raw Unicode box draw — CJK-safe) |

256-colour, if present: slightly warmer paper background (`235`) so the sticky banner is the only loud surface. Never require 256-colour.

Do **not** repaint every 500ms tick. Snapshot rule from ADR-0010 stays: paint only when due set, dismissed set, collection, Bound File, Current Result, selection, status, print buffer, or prompt changes — plus `KEY_RESIZE`.

Display Name clipping must use East Asian width (`unicodedata.east_asian_width`), not `len()`. Input uses `get_wch()` so Chinese text in Note/Contact works on macOS.

## Architecture (View only)

Composition root unchanged: `PIM()` → `App(pim)` → `Terminal(app)` → `run()`.

```
view/
  terminal.py       # command dispatch, prompt stack, wizards, dismissed, run()
  stdin_reader.py   # non-TTY / e2e path only
  layout.py         # region model shared by curses and text fallback
  keys.py           # empty-prompt accelerators → existing commands
  curses_ui.py      # windows, colour pairs, get_wch loop, dialogs, help overlay
  textwidth.py      # display width / clip (CJK)
```

No fifth top-level package. `model` and `controller` do not import curses. `App` gains nothing except possibly `select_row` already there.

```
Terminal.run()
  if stdin.isatty() and stdout.isatty() and curses available:
      CursesUI(terminal).run()     # timeout(500), get_wch, wrapper restores tty
  else:
      start_stdin_reader(...)      # today’s e2e path
      Queue.get(timeout=0.5)
```

`curses.wrapper` (or equivalent try/finally `endwin`) must restore the terminal on exception. User-facing failures still become one English status line; they do not dump a traceback into curses.

Clock: View still injects `now` for tests; the live TTY may show HKT clock in the title from `datetime.now(HKT)` **only in the View**, never in `model`.

## Risks

- **curses vs e2e:** mitigated by `isatty()` fallback; never let tests take the curses branch.
- **macOS `_curses`:** present with CPython 3.12; developer manual already pins macOS.
- **Wide characters / combining marks:** clip with East Asian width; test a CJK name in unit layout.
- **Letter-key collisions:** accelerators only on empty prompt; full verbs always work for the demo video.
- **Course “no extra features”:** this is HCI quality for the designed terminal (already in scope), not a new story. Do not add mouse, config files, themes, or a command palette.
